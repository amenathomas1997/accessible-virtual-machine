# AVM code audit, November 9, 2026 (third)

Read-only audit of the working tree of `next`: `55b06b4` (0.4.41) plus the uncommitted fixes for the ten "Fix first" findings of AUDIT-2026-11-09-second.md. Five independent reviewers, pointed at what earlier audits said they had not read closely: the uncommitted fixes; the less-visited machine code (backups, pruning, second drive, reinstall, RFB, clipboard); every line of Settings, the Setup Wizard, the Tour and Describe Screen; the devices path end to end; the install scripts, `autounattend.xml`, the Windows guest helper, the test jobs and Tools. **Independent review of the fixes:** a read-only reviewer traced all 33 against the code and the report. It passed 26 and found six holes, all corrected: `avmctl`'s new limit could never fire, since the client socket had no receive timeout and `read` blocked for good (the socket now times out every 5 seconds and `readLine` rides the timeouts to its deadline); the background test's "the choice is saved" check now read the user's own setting (dropped, as nothing is written in a test); the Bluetooth half of #4 (a keyboard given back for want of a Mac keyboard now waits in Return Devices and goes back at the next Bluetooth arrival, the Mac's keyboard waking); `waitForQMPJobToEnd` spun out its limit with QMP gone (it stops with the start); the Remote Desktop test kept the password when the start failed; the Settings hint named the backup folder but not the corrected disk size. Three it noted as left by design: a forged Windows Apps reply remains possible in a multi-account guest (replies land in `apps`, which Users can write; it would be a false "opened" or "failed", spoken, not code run); a few Authenticated-Users-writable folders under `C:\Windows` (`Tasks`, `tracing`, the spool colour folder) still pass the path rule; the wizard's close box and Command-W still cancel a download without asking, since only Cancel and Escape were named.

## Fix first

1. ✓ **Keep It can lose the session it promises to keep.** `VM/VMManager.swift:4938, 4988-5000`, `AVM/QEMUSavedState.swift:131-137`. The empty marker is written before the load and stays while the question waits, which with Start When AVM Opens and nobody at the Mac may be hours. A Quit from the alert, a Force Quit or a Mac restart meanwhile leaves the marker, and the next Start says the session couldn't be carried on and deletes it. Fix: remove the marker, or write a distinct "asked" word that `plan()` keeps, before the alert; recreate it only on Start Fresh.
2. ✓ **A refused Save sends devices from an earlier save back into the machine.** `VM/VMManager.swift:4857, 4810`. `devicesGivenUpForSave` is cleared only after a failed save, never after a successful one, and set only after the room check. Save succeeds with a braille display in the machine; days later a Save is refused for room, and `sendBackDevicesAfterFailedSave` seizes that display from VoiceOver with no question, or says devices "couldn't go back" that were never sent. Fix: clear it at the top of `performSaveStateAndStop` and after a successful snapshot.
3. **GuestWatch "starts" Orca on GNOME with a toggle shortcut, which turns it off.** `AVM/GuestWatch.swift:252-262, 196-208`, and the fallback at the end of `startReaderAfterApply`. Orca dies, the setting is still on, Super-Alt-S sets it off; AVM says starting it didn't work and GNOME starts no reader at the next login. GNOME's toggle semantics are inferred, as in the Apply fix. Fix: move Apply's gsettings off-and-on into `startScreenReader`; drop the shortcut for Orca.
4. **Both held keyboards go back when the Mac's own keyboard drops.** `AVMUSBHelper/BluetoothHold.swift:473-490`, `KeyboardHold.swift:388-413`. Each watch excludes every held device and decides alone. Mac mini, Bluetooth keyboard for the Mac that sleeps, USB keyboard for Windows, a Mantis through Bluetooth Devices: six seconds later both go back. The keyboard for Windows re-takes itself; the Mantis doesn't, because `helperLetGo` re-sends only for "it disconnected" (`AVM/BluetoothDevices.swift:379`). Fix: one decision across both holds, returning the keyboard for Windows first, and treat "no other keyboard" like a disconnect on the AVM side.
5. **Apply on Linux outside GNOME kills Orca and can't start it, then gives GNOME advice.** `AVM/ScreenReaderSetup.swift:217`, `AVM/GuestWatch.swift:255`. KDE, XFCE and MATE guests end every Apply silent, told to press a shortcut they don't have. Fix: start Orca directly as the signed-in user over the agent (`setsid orca --replace` with the session bus and display), and word the help per desktop.
6. ✓ **Settings writes a new shape to a machine that started while the sheet was open.** `views/SettingsView.swift:1738`. `keptShape` uses `isRunning` from sheet open; `startedMeanwhile` guards disk, Secure Boot and template but not cores, memory, camera, microphone or 3D. The user saves memory 8 to 16 while an `avmctl start` or Dock launch has started it; a later Save with open apps and the next Start fail the load with QEMU's words, and Keep It loops. Fix: `(isRunning || startedMeanwhile) && shapeChanged`, re-checked before the save.
7. ✓ **Two test jobs flip the user's real settings, and a killed test never puts them back.** `AVM/SaveResumeTestJob.swift:1553-1555, 1667-1670`, `Tools/run-all-tests.sh:300-313`. The restore is a `defer`; `pkill` on an overrun sends SIGTERM and no `defer` runs. The before-updates restore point, kept off by default because Windows twice didn't come back, is then on for the user's own machines, or AVM runs in the background unasked. Fix: pass the choices through `NSArgumentDomain`, or have run-all-tests.sh save and restore the two keys.
8. ✓ **Remove AVM's default button removes AVM.** `AVM/RemoveAVM.swift:32-35`. Return on what sounds like an information dialog unregisters the helper, trashes settings and the app, and quits. Every other destructive alert puts Cancel first. Fix: Cancel first.
9. ✓ **Escape in the Setup Wizard cancels an hour-old download without asking.** `views/SetupView.swift:361-368, 411-415`, `views/ISODownloadView.swift:107-112`. "Keep Going in Background" promises the download continues, but the wizard's Cancel has the Escape shortcut and `.onDisappear` cancels all three downloaders. Fix: ask when a download is running, or keep the download alive past the wizard.

## Medium-low

10. ✓ **The dashboard reads a machine's folder on the main thread for the Disk column.** `AVM/MachineDrives.swift:135-141`, `views/ContentView.swift:582`. For a machine not run this session, every redraw resolves the folder and reads `disk-usage.json`; a gone network share or spinning-up drive stalls the dashboard, menus and speech (blocking inferred). Fix: read it in `StorageWatch` off-main and publish.
11. **Windows Apps' path keys accept user-writable locations, and replies can be forged.** `Resources/windows-apps/AVMWindowsApps.cs:201-217, 257`. `C:\ProgramData\x.exe` passes `KnownApp`, `running.txt` is still Users-writable, so another account can plant a stand-in the victim's helper launches in their session. Multi-account guests only; inferred. Fix: accept paths only under Program Files, Windows and the user's own profile; write replies in `requests`.
12. **A restore whose saved-state discard can't be confirmed is undone by the next Start.** `views/SettingsView.swift:1216-1220`, `AVM/QEMUSavedState.swift:166-182`. A stopped saved machine has no marker; if the delete fails, the next Start loads the old session over the restored disk and says it is resuming. Rare, inferred. Fix: write `loadedMarker` with `carriedOnWord` when `discard` can't confirm.
13. ✓ **The second drive is shown as 100 GB but can be made much smaller, silently.** `views/SettingsView.swift:150, 396-398, 1763, 1986`. The seed exceeds the stepper's maximum, the control reads 100, the drive is made at the maximum and the spoken result gives no size. Fix: clamp to the maximum when the controls appear and say the size.
14. **`avmctl` now waits for ever on a hung AVM.** `AVM/ControlServer.swift:424`. The 0.4.41 fix removed the client's limit entirely. Fix: a limit of minutes with a message naming it, or check AVM's pid between reads.
15. **Keep It ends QEMU while a timed-out snapshot-load may still be writing.** `VM/VMManager.swift:5002`, `abandonFailedStart`. A kill mid-`goto_snapshot` leaves a qcow2 QEMU must repair (inferred). Fix: wait, bounded, for `avm-load` to leave running before ending QEMU.
16. **A QEMU that died during the load loads the same state at every Start.** `VM/VMManager.swift:4996-4999`. The new branch removes the marker for any non-starting state; the earlier branch keeps it for `.error` on purpose. Fix: mirror that condition.
17. **"X is now in A" can be said for a device already being released.** `AVMUSBHelper/main.swift:345, 536-539`. ATTACHED arriving after `beginRelease` overwrites `.releasing`. Fix: ignore ATTACHED while releasing.
18. **Drive C's "same" answer is spoken as a failure.** `AVM/MachineDrives.swift:206-216`. Grow the disk, restore an earlier point, Start: Windows says `same` and AVM says a partition is in the way. Fix: treat `same` as done; clear `extendDriveC` when a restore puts the size back.
