## Fix first

1. ✓ **A QEMU that stops reading can freeze all of AVM.** `VM/VMManager.swift:3822`. The QMP write retries `EAGAIN` forever with `usleep`, on the main actor, with no deadline. Unanswered commands from GuestWatch, DiskWatch and the Windows keyboard pile up until the socket buffer fills (inferred, roughly 10 to 20 minutes). Then there is no menu, Force Stop, Quit or speech, for any machine. It contradicts the last audit's "every loop is bounded". Fix: a 2 s deadline with `await Task.sleep` and a socket identity check, then throw and mark the socket unusable, since half a line may be in it.
2. ✓ **A main-thread hang while the keyboard is in a machine has no way out.** `focus/FocusLockManager.swift:347-353, 586`. Force Quit, process switching and session termination are all disabled, and the escape chord's handler needs the main thread. 0.4.39 was this kind of hang. A blind user is left with the power button. Fix: drop `.disableForceQuit` and `.disableSessionTermination`.
3. ✓ **A failed Save can leave a snapshot that a later Start loads over newer work.** `VM/VMManager.swift:4733-4741`, consumed by `AVM/QEMUSavedState.swift` `plan()`. The delete in the catch is `try?` and is skipped if the node name fails, and nothing durable says the tag must not load. The user is told the save failed, works for days, and a later Start says it is resuming. Needs a save past its limit and a failed delete, so rare, but the loss is total. Fix: write `loadedMarker` before the delete.
4. ✓ **Restore can still stop half applied.** `VM/VMStore.swift:749-788`. The saved session is discarded before anything can fail. If the second drive rolls back and the first disk then fails, D: is permanently in the past and the user hears nothing was restored. A throw from the resume note or swap after both rollbacks leaves the live TPM, the BitLocker case fix #4 aimed at, and can swap nvram without the TPM. Fix: prove both images are writable and hold the tag before `beforeRollback`; swap staged files first; make the note a `try?` written last; clean up in a `defer`.
5. ✓ **Apply Screen Reader Setup moves settings away before it knows the unpack works.** `AVM/ScreenReaderSetup.swift:119-145`. A failed unpack leaves NVDA or Orca on defaults or partial settings, and the spoken next step is wrong. A partial unpack containing `nvda.ini` reports success. A second Apply also deletes the true original at `-before-avm` (lines 122 and 143), against the file's promise. Fix: unpack to a new folder, validate, then swap; never replace an existing `-before-avm`.
6. **Helper death may not return USB devices.** `AVMUSBHelper/main.swift` has no SIGTERM handler ✓, `restart()` exits with live streams, and `AVM/USBHelperClient.swift:311` unregisters straight after disconnecting ✓ while saying devices were returned. A blind user could lose a braille display or keyboard. Inferred: whether macOS re-matches the device after the process dies. Test first with `kill -9` and an attached device. Fix if confirmed: drain streams on SIGTERM and in `restart()`, and wait for an empty status before unregistering.
7. ✓ **A macOS saved session is deleted on any resume error.** `AVM/MacGuest.swift:546-554`. Any non-locked error removes the file and cold-boots without asking, and the file is also removed before `resume`'s result is known. A transient error costs the whole session. Fix: ask (Try Again, or Start Fresh and Discard), and remove only on success.
8. ✓ **A failed before-updates restore point is silent.** `AVM/GuestWatch.swift:335-339`. It is only logged, including the refusal for too little free space. The user believes updates are protected and finds no point after one breaks Windows. Fix: say it once per run, with the reason.
9. ✓ **A healthy machine with no working guest agent gets a false "looks stuck".** `AVM/GuestWatch.swift:101, 165`. Failed `guest-exec` plus a still desktop for the limit tells the user to press Command-Shift-R, which loses unsaved work. Fix: arm the watch only after the agent has answered once this run.
10. **Sparkle's window can take the keyboard from a machine, and AVM's words about it are often untrue.** `app/AVMUpdater.swift:74-78, 152, 184-197`. ✓ for the announcement text being unconditional. Inferred from Sparkle's source: after long idle its alert takes focus with Install focused while the machine has the keyboard, and "The update window is open" can be said with no window, which then never appears on unlock. Fix: a `SPUStandardUserDriverDelegate` that holds the window while locked, chooses words from what is shown, and brings it up on unlock.

## Medium-low

11. **The request owner check can be bypassed in multi-account guests.** `Resources/windows-apps/AVMWindowsApps.cs:131`. The lockdown makes a planted file SYSTEM-owned and Users-writable, and a user can rewrite a genuine pending request. Fix: put requests in a folder Users can't write, and validate the launch key against known apps.
12. **The relocated-drive repair happens only at Start.** `views/SettingsView.swift:1202`, `AVM/WindowsReinstall.swift:76`, `AVM/MachineDrives.swift:54`. A Restore before Start can later load the old saved state over the restored point. Fix: one computed resolved path, or rewrite on load and mount.
13. ✓ **Mac sleep during a long restore point can leave the guest paused while AVM says Running.** `AVM/SleepCoordinator.swift:102`, `VM/VMManager.swift:1851`. `stop` times out and stays queued (QMP ordering inferred). Fix: skip or wait for machines taking a point.
14. ✓ **Offline, a good cached screen reader installer is ignored.** `AVM/ScreenReaderInstallers.swift:80-102, 189-197`. A failed lookup falls to the pinned version, whose filename differs, so Windows may install with Narrator only. `removeOlderCopies` (243) removes every other version, even a newer one. Fix: a sidecar of version and checksum, and numeric compare.
15. **Interrupted macOS auto-setup names an account that may not exist, and VoiceOver is never offered again.** `AVM/MacAutoSetup.swift:97-106`, `AVM/MacGuest.swift:487-492`. Fix: set the offered flag only on success.
16. **A failed Save and Quit leaves devices detached and doesn't say so.** `VM/VMManager.swift:4717-4721`, `app/AVMApp.swift:1355-1383`. Fix: reattach, or say so.
17. **Disk checks in SwiftUI bodies block the main thread on a sleeping volume.** `VM/VMConfiguration.swift:416-445`. Fix: compute off-main.
18. **Guest-driven Bluetooth frames queue without limit in the root helper.** `AVMUSBHelper/BluetoothHold.swift:359-387`. The backlog also delays the socket close. Fix: a pending limit and a stopped flag.
19. **A stuck USB release after an unplug is never set aside.** `AVMUSBHelper/main.swift:353`. DEVICE_LOST overwrites `.releasing`, so the device stays "already attached" and the helper never idles. Fix: test the stream, not the state.
20. **The helper trusts older signed AVMs, including ones with `disable-library-validation`.** `AVMUSBHelper/main.swift:60-65`. Needs code already running as the user; inferred. Fix: a minimum build.
21. **Job dismissal is partial.** `VM/VMManager.swift:4566, 4582-4583, 4738`. A query timeout reads as "job gone", `avm-unsave` has no dismiss, and same-id jobs can race. Fix: unique job ids per call.
22. **Force Stop then Start within two seconds can hit the old QEMU's disk lock.** `VM/VMManager.swift:1812-1848`. The user hears "stopped unexpectedly" with no reason (inferred). Fix: wait, bounded, for doomed processes.

## Lower

28. Start carries on past a stop during `applySoundLevels`, which can leave the keyboard seized (`VM/VMManager.swift:1633`).
29. A torn-down command's `qmpRelease` can unlock the next QEMU's command (`VM/VMManager.swift:3758`).
30. The failed-load fallback never checks that the machine runs (`VM/VMManager.swift:4826-4827`).
31. What's New takes the front during quiet login.
32. The `SendToMachine` alert takes the keyboard with nothing spoken when VoiceOver is off.
33. The log stops at 5 MB, losing the newest lines (`AVMLog.swift:308`).
34. Save Screen Reader Setup can report success with a stale zip, and a nil read counts as end of file (`AVM/ScreenReaderSetup.swift:40, 64-87`).
35. Linux setup uses UID 1000 rather than the signed-in user, and `/tmp/avm-sr-setup.tgz` stays after Save (`AVM/ScreenReaderSetup.swift:74, 140`).
36. Save skips the lockdown Apply does, on a predictable SYSTEM path (`AVM/ScreenReaderSetup.swift:66-69`; multi-account guests, inferred).
37. NV Access's `version` isn't validated before naming a Mac file (`AVM/ScreenReaderInstallers.swift:144, 190`; hardening only).
38. USB streams have no console-user watch after a fast user switch (`AVMUSBHelper/main.swift:246`).
39. `attach`'s slow libusb work blocks the registry queue.
40. A background user's keyboard request locks out the console user (`AVMUSBHelper/KeyboardHold.swift:199`).
41. Release checks never assert the entitlements the helper's trust depends on (`Tools/build-installer.sh:389-403`).
42. The Windows app stand-in has no `SO_NOSIGPIPE` and can die on a write (`AVMWindowsApp/main.swift:145`).

## Checked and found sound

Caps Lock lifecycle; control-socket authentication; shell injection from machine names; log privacy; helper frame parsing and `usbstream.c` bounds; socket path checks; the XPC gate; publish gates; the zip-slip regex as escaped; answer-file residue scrubbing; archive path handling; download hashes and HTTPS; pipeline time limits; continuations in QMP waiters; state after await in pause and resume. From the ten fixes: #1's normal path, #5, #6's close ordering, #7, #9's gone-drive wording, #10, the helper 7 to 8 upgrade, icacls flags and quoting, and #3's ordering inside `startVM`.

`AVM/USBPlugPrompt.swift` had only a light pass, and `AVM/USBHotPlugWatcher.swift` only its IOKit release paths.
