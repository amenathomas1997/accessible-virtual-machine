# AVM code audit, November 10, 2026

Read-only audit of `b904e9d`, version 0.4.44 (64) as first built. Five independent reviewers: the 0.4.43 and 0.4.44 changes (`git diff 0311bcf..b904e9d`); the machine lifecycle core (all of `VMManager.swift`, sessions, saved state, restore points, backups, quit); every trust boundary (root helper, control socket, guest to host, host-to-guest scripts, secrets, updates and downloads, networking); install pipelines and guest integration; and what the user touches and hears, with input capture. Nothing in the repo was built, run or changed by the reviewers.

**Status: all 42 fixed on `next`, uncommitted, the same day, some in part (listed under "Left"); #1 to #42 shipped in 0.4.45 (2026-11-11); #43, found while testing, fixed on `next` that day, uncommitted.** No High findings. 42 findings: 8 "Fix first", 10 Medium-low, 24 Lower. One change was made because of this audit before 0.4.44 was published: its release note no longer says Orca is restarted only when GNOME's setting is on (#6).

**How the eight were fixed** (each site carries a dated comment naming its number):

1. New patch `libslirp-v4.9.1+no-host-loopback-addresses.patch`: with the switch on, `sotranslate_out4` refuses 127/8 and 0/8, `sotranslate_out6` refuses `::1`, `::` and IPv4-mapped and IPv4-compatible addresses, and a ping of any of them is dropped. libslirp rebuilt by hand, the old library kept as `~/Developer/sysroot-3d/libslirp.0.before-loopback-addresses.dylib`, the patch checked against a fresh source and recorded with `--mark-built`. 2. A guest reads the Mac's clipboard only while its change count is the one AVM last offered (`mayRead`), and writes it only while someone is at that machine: it has the keyboard, or the keyboard for Windows types into it (`mayWrite(from:)`, with two seconds' grace after leaving for a copy in flight). Each connection has its own `MachinePasteboard`, since CocoaSpice's calls don't say which machine they come from. 3. The gate finds the edition by wimlib's `Edition ID` when the English name isn't on the disc (`WindowsEdition.imageName`), and the answer file's `/IMAGE/NAME` gets the disc's own name, XML-escaped. 4. `startOverInterruptedSetup`: a report with `specialize-started` and no `specialize-done` at Start removes the marker, the report, the firmware settings and the TPM and installs again from the DVD with the answers still on the volume, saying so; without the answer file or DVD it says Reinstall Windows may be needed. 5. The macOS question discards only on Start Fresh; any other answer but Try Again keeps the session and ends the start. 6. Linux has a chosen reader, Orca, so the "never started" check runs; the stop path leaves an Orca whose GNOME setting is off. 7. `lock(machine:)` names the machine it locks for, from its session, and refuses one that is neither running nor paused. 8. The hold goes by machine id (`Announcer.keyboardInID`, GuestWatch's key), and GuestWatch reads the machine's name each tick.

Also fixed, because AVM's own live runs kept hitting it: #16, the start's handshake reads now wait a minute, not 5 seconds (swtpm's 2 seconds unchanged).

**Their review:** a read-only reviewer passed #3, #5 and #8 and found holes in the other five, all corrected above. #2: a guest's agent could announce itself at will, and each announcement marked the Mac's clipboard as offered (the offer at an agent's connection is now made only with someone at that machine, and otherwise owed to the next entry); the write gate was for any machine, not the one in use; with the keyboard for Windows held and AVM not in front, a paste found nothing (the clipboard is looked at each second while it is held); a copy made just before leaving could be dropped. #1: ping skipped the check. #4: "can't finish" was followed by "carrying on" and progress lines (the sentence is now hedged, and the carry-on line isn't said after it), and the report was deleted before the marker was known gone. #6: at a GNOME login screen the once-only check was spent before anyone signed in (it now waits for a person's session, by `loginctl`), and other desktops heard the advice at every Start (once per machine now). #7: a paused machine could no longer be entered.

## Found while testing

43. **A Start hangs in QEMU's sound set-up when the Mac's sound output doesn't answer.** Seen three times on 2026-11-10 in AVM's live jobs: QEMU never answers QMP, and the Start fails minutes later with "Timed out waiting for a QMP response". A sample of the stuck QEMU shows its main thread in `coreaudio_init_out`, `AudioDeviceCreateIOProcID`, waiting on a message to coreaudiod. First put down to the locked screen; that was wrong. On 2026-11-11, with the screen locked for a minute, Core Audio and QEMU's sound set-up answered in under a tenth of a second; later, unlocked, the default output (a wireless headset whose USB receiver stays connected while the headset is off) didn't open in 20 seconds while the built-in speakers did, and it opened at once when the headset was back. This is very likely what earlier audits recorded as "a fresh copy's first QEMU start can time out the QMP handshake".

    **Fixed 2026-11-11, on `next`.** Before QEMU is launched, `SoundOutputDevices.answers(within:uid:)` opens the output QEMU will open (the machine's chosen device, or the default), on a thread of its own; if it hasn't opened in 8 seconds the Start is refused, naming the device and what to do. `Stalls.finishes` gives up on work that never comes back, and one stuck look isn't joined by more. Verified: a unit test of `Stalls`; a live job with a simulated stall (`--test-sound-stall`); and one real case, when the headset went off during the test: a job with no simulation was refused 8.4 seconds after its Start. Not changed: QEMU still opens its sound on its main thread, so an output that stops answering between AVM's look and QEMU's own would still hang the Start; and a machine already running isn't affected either way.

**Checked by hand:** findings marked ✓ were re-read against the code by the author of this report after the reviewers. "Inferred" means the AVM side is traced and the outcome depends on platform behaviour that was not run.

**Verdict on 0.4.43's and 0.4.44's fixes:** three recorded fixes don't hold. The loopback block (eighth audit #2) refuses only the gateway address, and a guest can name 127.0.0.1 itself (#1). The Orca fix (#16) sits in a block no Linux machine reaches (#6). The rename fix (#18) broke the match that holds AVM's routine lines while a screen reader talks (#8). Two more are incomplete: the add-on exclusion (#20) is a deny-list a hostile archive walks around (#13), and the keyboard test of #15 still counts devices the helper doesn't (#15 below). The Keep It fix (#4) was right, but the same fault sits at the macOS question (#5). The lifecycle fixes (#9, #13, #14, #19, #26) were traced end to end by two reviewers and hold.

## Fix first

1. ✓ **The loopback block is bypassed by addressing 127.0.0.1 directly.** `Tools/sysroot-patches/qemu-10.0.12-utm+no-host-loopback.patch`; libslirp 4.9.1 `src/socket.c:968-1008`. `sotranslate_out4` refuses only a destination equal to the gateway alias (10.0.2.2) or broadcast. A guest with root or Administrator that puts a packet for 127.0.0.1 (any 127/8), 0.0.0.0 or `::1` on its network card is outside that test, and libslirp connects on the Mac to that address. Machine A still reaches machine B's "This Mac only" Remote Desktop and any loopback-only server on the Mac. 0.4.43's note says machines can no longer do this. The fix's live check tried only 10.0.2.2. Library code read; the connect and the guest accepting replies inferred, not run. Fix: patch libslirp so that, with the switch on, 127.0.0.0/8, 0.0.0.0/8, `::1`, `::` and `::ffff:127.0.0.0/104` are refused; prove it from the Debian machine with a crafted destination.
2. ✓ **A guest can read, and replace, the Mac's clipboard at any time, not only when entered.** `views/VMView.swift:1040-1070`; CocoaSpice `CSSession.m:189-243`. `cs_clipboard_request` answers any request from the guest's agent with the delegate's data, and `AVMPasteboard.data(for:)` returns the current clipboard whenever sharing is on and the copy isn't marked private. Nothing checks that AVM offered this copy, that the machine has the keyboard or that its window is key. A guest that polls gets everything copied in any Mac app while it runs, including passwords from apps that don't set the private marks; `cs_clipboard_grab` lets it overwrite what was just copied. Both handlers read; that spice-glib passes an unsolicited request through is inferred. Fix: serve reads only while the change count equals the one AVM last offered on entry; accept guest writes only while that machine holds the keyboard or its window is key.
3. ✓ **A Windows disc in French, or any language that translates edition names, can't be installed, including the one AVM downloads in the Mac's language.** `VM/WindowsInstallPipeline.swift:963-979`, `VM/VMConfiguration.swift:577-583`, `views/WindowsAutoDownload.swift:181, 201-233`, `Resources/autounattend.xml:107-108`. The gate compares English names with the disc's image names ("Windows 11 Famille", "Professionnel"), and hard-stops after the 4.5 GB download and the ISO build with advice that is wrong. AVM's side read; the translated names inferred from a French Windows 10 listing, no French disc read. Fix: choose by wimlib's language-independent Edition ID and write `/IMAGE/INDEX`; run the check before the download says "ready".
4. ✓ **A stop during Windows' specialize pass leaves a Windows that can't finish, and AVM says it is "carrying on".** `VM/VMManager.swift:1551-1585, 3432-3450, 3609-3613`; `Resources/autounattend.xml:135`. The marker and `specialize-started` are already written, so the next Start treats Windows as installed, deletes the answer file, and counts minutes. Windows doesn't re-run an interrupted specialize; it shows "The computer restarted unexpectedly" and loops. Only Reinstall Windows gets out, and nothing AVM says points there. AVM's side read; Windows' behaviour inferred. Fix: `specialize-started` without `specialize-done` at Start means start over, before the answer file is removed, said aloud; otherwise say Reinstall Windows is needed.
5. ✓ **An aborted "couldn't resume" question discards a saved macOS session.** `AVM/MacGuest.swift:561-573`. The eighth audit's #4 at a site its fix missed (two reviewers): only Try Again keeps the state, so a USB question's `abortModal` ending this alert falls through to deleting `SavedState.vzvmsave` and a cold start. `abortModal` ending the innermost modal inferred, as for #4. Fix: discard only on `.alertSecondButtonReturn`; otherwise keep the state and end the start.
6. ✓ **The Orca fix (#16) is in code no Linux machine reaches, and the path that does restart Orca ignores the setting.** `AVM/GuestWatch.swift:47, 202-234`. `chosenReaders` is empty for Linux, so the "no reader a minute after sign-in" block never runs: #16 described a path that didn't exist, and a Linux machine whose Orca never starts gets neither a start nor advice. The stop path forces GNOME's setting off and on whatever it was, so an Orca turned off with Super-Alt-S comes back in half a minute, and where the greeter's Orca was seen, an account with Orca off has it turned on after sign-in. 0.4.44's note was corrected before publishing. Fix: give Linux a chosen reader so the block runs; in the stop path read the setting first on GNOME.
7. ✓ **`lock(machine:)` records the right machine but speaks and stores the current machine's name.** `focus/FocusLockManager.swift:356, 371-380`. Start A, then B before A is up: A's window locks for A, and the user hears "Entering B" while typing into A; `Announcer.keyboardIn` stays B until unlock, so held lines follow B's screen reader. `enter()`'s one-second deferred lock can also lock for a machine that ended in that second. Name source read; the order of onAppear and windowDidBecomeKey inferred. Fix: take the name from the session for `machine`; refuse if it is gone or not running.
8. ✓ **Renaming a running machine switches off "hold AVM's updates while its screen reader talks".** `AVM/GuestWatch.swift:45, 88, 110`; `Announcer.swift:367-370`; `AVM/MachineSessions.swift:55-67`. GuestWatch keeps the name from Start in `readerRunningIn`; the #18 fix moves `keyboardIn` to the new name, so `holds()` is false until the next Start and routine lines are spoken over NVDA, JAWS or Orca. GuestWatch's own lines keep the old name. A regression from #18. Fix: key both by machine UUID.

## Medium-low

9. **A machine that finishes starting takes the keyboard whatever the user is doing in AVM.** `AVM/MachineSessions.swift:259, 409-438, 468-471`; `views/VMView.swift:589-591`. `showFirstTime` stands down only when another machine has the keyboard. Under a Settings or wizard sheet the rest of a password being typed goes into the guest; under an alert the lock engages with "Entering X" though the keys are in the alert; What's New is interrupted; from another app AVM activates and the lock refuses in the same turn. A window becoming key over a sheet inferred. Fix: with a modal, a sheet or AVM inactive, show without key and say "X is running. Press Command Shift E to enter it".
10. **Type Clipboard and Repair for AVM type US key positions into machines set up with another keyboard.** ✓ header. `AVM/TypeText.swift:11-43`; `AVM/GuestRepair.swift:35-38, 86`. Installs follow the Mac's layout since 2026-10-25; on a German, French or British machine a password typed into a sign-in box is wrong, with "Typed N characters" and the success sound. Fix: keep the guest's layout in the configuration and map by it; until then warn or refuse when it isn't US.
11. ✓ **Nothing keeps the Mac awake during an unattended install or a long download.** No power assertion in the app. A MacBook idle-sleeps, the machine is paused and downloads drop; the 60- and 75-minute alarms count time asleep and can fire falsely. Idle sleep with QEMU busy inferred. Fix: hold `beginActivity(.idleSystemSleepDisabled)` for media builds, installs and AVM's downloads; count the alarms on a clock that stops in sleep.
12. **The big downloads have no resume.** `views/WindowsAutoDownload.swift:191-262, 444-448`; `views/LinuxISODownload.swift:247-253, 316-318`; `AVM/MacGuest.swift:276-337`. Any drop at 25 of 26 GB starts again from zero. Fix: the screen reader downloads' pattern, with resume data and "carrying on from N percent".
13. **The add-on exclusion (#20) doesn't keep programs out of a saved screen reader setup.** `AVM/ScreenReaderSetup.swift:140, 233-235, 151, 274`. The archive's bytes are the guest's, so only Apply's checks count. `./addons/…` or `addons./…` passes the entry test; NVDA's `updateCheckState.pickle` is neither excluded nor safe to load (from NVDA's source as recalled, not run); Orca's `.pyc` files aren't excluded (lower confidence). Fix: an allow-list at Apply and on the Mac after copy-out, with entry names normalised first.
14. **Apply's clean-up deletes as SYSTEM in a folder it has just given the user full control of.** `AVM/ScreenReaderSetup.swift:248-267`. In the two-second wait a hostile standard account can turn `sr-new-<guid>` into a junction and make the script throw; `finally` runs `Remove-Item -Recurse -Force` through it. Inside the guest only; PowerShell 5.1 following the junction inferred. Fix: clean up as `AvmRemoveTree` does, after a link check on the folder itself.
15. **#15's keyboard test still counts devices the helper doesn't.** `AVM/BluetoothDevices.swift:498-512`; `AVMUSBHelper/KeyboardHold.swift:104-109, 173-188`. `list()` returns every device with a keyboard collection (gaming mice, scanners); the helper's rule needs primary usage Keyboard. With such a mouse, the refused re-send and "stayed on the Mac" still repeat. Fix: add a flag computed by the helper's own rule to each entry.
16. **A Start gives QEMU about 5 seconds to answer, and swtpm 2.** `VM/VMManager.swift:3821-3830, 2658-2663`. A slow first launch fails the Start with "Timed out waiting for a QMP response"; Start When AVM Opens and Restore's restart don't retry. The eighth audit's own live run hit this. That QEMU answers only after machine init inferred. Fix: 60 seconds for the handshake reads, 10 for swtpm; both already end at once if the process exits.
17. **A backup, Export or Duplicate can begin on a machine in the middle of a Restore or Reinstall.** `AVM/MachineArchivePanels.swift:64, 185-190, 249`; `views/SettingsView.swift:1256`. None looks at `RestorePoints.restoringIDs` or `WindowsReinstall.preparing`; the hourly backup can copy a disk being rolled back, mark it whole and trash older good backups. Narrow window. Fix: refuse while either is set; make Restore's restart respect `busyMessage`.
18. ✓ **Delete doesn't check for a QEMU left running from before AVM last closed.** `views/ContentView.swift:788-832`; `VM/VMStore.swift:507`. The folder goes to the Trash with QEMU still writing it, and nothing can end that QEMU afterwards. Export refuses this case. Fix: end it first, saying so, or refuse.
