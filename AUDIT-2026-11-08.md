# AVM code audit, November 8, 2026

Read-only audit of `next` at `c8df930` (0.4.40, as published), by six independent reviewers cutting the code differently from the three earlier audits (AUDIT-2026-11-01.md, AUDIT-2026-11-05.md, AUDIT-2026-11-05-second.md): everything changed since 0.4.37 (the second audit's fixes and 0.4.38 to 0.4.40); the machine core (VMManager, QMP, the guest agent, saved state, sessions); the app layer (updater, control socket, logging, views, quit); everything AVM puts inside a guest; the privileged helper, native code and release tooling; storage, data integrity and downloads. Line numbers are from that commit.

**Status: the ten "Fix first" findings are fixed on `next` (2026-11-08, same day), the rest are open.** How each was fixed: #1 the stuck list is kept per machine and used on every pass until `running.txt` moves, a stuck file whose list equals `running.txt` is ignored, and the helper (version 8) deletes it at start-up and after every successful write; #2 the helper answers only requests owned by SYSTEM or Administrators, the lockdown passes `/L` to every icacls, removes reparse points found under `apps` (the link, not its target) and grants Modify to the folder and the files directly in it rather than walking a tree; #3 `startVM` rewrites `diskImagePath` into the relocated folder when the old path is gone and the file is there; #4 the second drive is applied before the first, and the staged copies are removed on any failure; #5 the helper treats an `IOException` on reading a request as "next pass" for ten seconds; #6 the read source's cancel handler and `stop` close the socket on the device's own `io` queue; #7 a `-stuck.log` with any content is collected; #8 a job past its limit is cancelled, polled to concluded and dismissed, and every catch around `runQMPJob` dismisses its id; #9 a gone drive says Force Stop, reconnect, Check the Disk, and a pause with room on the volume is called a disk error, not "full"; #10 a second AVM process with the same bundle identifier (no arguments, no test support folder) brings the first forward and exits before touching anything. Not done from #10: merging `configurations.json` on save. Items the earlier audits list as deliberately unfixed are not repeated.

**Not run live:** the helper's version 8 compile in Windows, the icacls lines, the owner check on a request written through the agent (SYSTEM's default owner may be Administrators, which is why both are accepted), a restore with a failing second drive, a cancelled QMP job, a stuck file, a second instance.

**Checked by hand against the code:** findings marked ✓ were re-read by the author of this report after the reviewers; "inferred" means the AVM side is traced and the outcome depends on platform behaviour (icacls, Win32 sharing, Sparkle, QEMU) that was not run. None was run live. Two reviewers reached #1 and #6 independently.

**Where the last two bugs came from:** the 0.4.39 Command-Tab fix and the 0.4.40 recursion were both in bulk-edited code shipped without a Windows run. Three of this audit's top five are in that same code (#1, #2, #5), and the C# helper's version 7 has still never been compiled. The first live start of a Windows machine on 0.4.40 is the real test of all of it.

## Checked and found sound

**Collateral from the 0.4.39/0.4.40 rewrites.** All eleven `openGuestFile`/`closeGuestFile` call sites keep their pre-rewrite semantics (throwing closes still throw, `try?` closes still swallow); no self-call or mutual recursion remains anywhere in the core; `leakedGuestHandles` is main-actor state touched only through main-actor methods, iterated as a value copy; qga's file ids come from a monotonic counter, so retrying a stale handle can't close a live one; "has not been found" is qga's own wording. Every loop in the core is bounded. The C# helper's `Write` (temp file then `File.Replace`) fails with `IOException` exactly when the agent holds `running.txt`, which the new catch handles; `last` is not advanced on failure so the write retries every second.

**The second audit's fixes** were each checked: iCloud refusal in the only storage picker and the evicted-disk check at Start; `werror=stop,rerror=stop` on both drives and not on install media; the SPICE write side; restore's `isSaving` re-check and the folder kept when the tag landed; all six helper calls through `ask(_:within:)`, continuation resumed once; `SuspendingClock` in the three deadlines; export refused while Setup runs; viostor and 3D staging under a random `C:\Windows\Temp` name; the owner check only on the Data volume; `bytesNeeded` logical on non-APFS; the volume UUID recorded and resolved (#3 above is the part it missed); the leftover `drive2.qcow2` adopted, and the disk found by serial first; folder-first restore points with `pending`; `checkRoomForMemory` before with-memory saves; the half ISO removed; NVDA/JAWS mutually exclusive; AVMRUN.PS1's exit codes; Reinstall busy at the top of `startVM`; the zip entry regex. The withdrawn "stale disk bus" finding stays withdrawn.

**Updater.** HTTPS feed, EdDSA key in Info.plist, `build-installer.sh` refuses a key change; verification and downgrade protection are Sparkle's; AVM never launches an installer; the raw-feed poll can only trigger a check Sparkle then verifies.

**Control socket.** `getpeereid` against the user's own uid on every connection, 0600, JSON dispatched on a fixed command string, `send-file` paths gated by `SendToMachineService.mayRead`; nothing reaches a shell or a QEMU command line unquoted.

**Logging.** `AVMLog.sanitize` at the single write point; no password, key or token logged (grepped); Read Screen, Describe Screen and Type Clipboard log counts, never text; the Claude key and Remote Desktop passwords live in the keychain, names and passwords go to the guest on standard input.

**QMP and QEMU.** Reply ids matched, half-read lines dropped, continuations resumed once; every user-controlled path through `qemuOptionValue`; the machine's name appears nowhere in argv; orphan reaping scoped by UUID and parent liveness, no PID files; process handlers hop to the main actor; starts cut short are checked at every step; stop ordering under `savingTask`/`takingRestorePoint`; saved state's marker-before-load protocol; both drives in every snapshot operation.

**Guest-side.** Every autounattend value XML-escaped and validated, the filled file parsed and every marker checked before `mcopy`; the answer file deleted in specialize after the last step that reads the DVD; `windows-setup.json` 0600 and forgotten once media is built. Every `agentRun` takes an argument array; Install Apps' URL, hash and switches single-quoted with doubling, HTTPS-only, SHA-256 checked in the guest. Linux user names, real names, host names, layouts regex-checked; passwords only as SHA-512 hashes; the chroot script in CDATA with quoted heredocs. macOS automatic setup clicks fields by placeholder from a fresh screenshot and types nothing when a label is missing. The saved NVDA setup is unpacked entry by entry refusing absolute, drive and `..` names. The Mac companion strips `/`, `:` and NUL from bundle names.

**Helper.** Code-signing requirement set before `resume`, built from the helper's own team; audit-token uid drives every ownership check; status filtered by owner; idle exit under the registry's lock with a re-check; `usbstream.c` bounds every string and path, checks `getpeereid` and `LOCAL_PEERPID` after connecting, frees in pairs; `StreamSocketCheck` refuses symlinks at every step; `KeyboardHold` forwards only page-7 usages from held devices, never built-in, never a braille display; frame parsing bounds length at 1024 and resyncs; `HIDReportDescriptor` bounds every read.

**Build and release.** `set -euo pipefail` throughout; dirty tree refused before and after the archive; signed inside out, `--deep --strict`, Team ID on every Mach-O, no library path outside the app; app notarized and stapled, DMG made from the stapled app and notarized again; Sparkle signature checked against the key in the plist and the last tag's; `publish-release.sh` requires the built commit to equal HEAD and the build number to exceed the feed's; `sysroot-sources.sha256` enforced for cached files too; every `rm -rf` on a validated non-empty root.

**Storage.** Entries come from a directory walk (`lstat`, links skipped), never from the manifest, so no zip-slip; the manifest's one path field reduced to its last component and the copy re-checked with `qemu-img info`; backing and data files refused; `configurations.json` written atomically with unreadable entries kept verbatim; free-space arithmetic in `UInt64` with a 512 MB spare; sparse copy with `SEEK_DATA`/`SEEK_HOLE` and `O_EXCL`; `isOwnTag` gates every folder path built from a snapshot name; Reclaim takes UUID-named folders only; the Linux checksum file comes over HTTPS from the ISO's own folder (it proves transfer integrity, not the server's honesty, and the spoken words say exactly that); the Windows `.esd` over plain HTTP is gated by the catalog's SHA-1.
