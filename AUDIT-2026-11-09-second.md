# AVM code audit, November 9, 2026 (second)

Read-only audit of `next` at `55b06b4` (0.4.41, as published), by five independent reviewers: the 0.4.41 fixes themselves; the machine core; the app layer and accessibility; the root helper, USB and release chain; storage, install pipelines and guest-side work. Nothing was built, run or changed.

**Status: the ten "Fix first" findings are fixed on `next` (2026-11-09, uncommitted), the other 21 are open.** No High findings. 31 findings after merging three that two reviewers found separately: 10 "Fix first", 9 Medium-low, 12 Lower.

**How the ten were fixed:** #1 only the server keeps the 15-second limit. #2 the setup is checked before the reader stops, and Apply starts it again and confirms it, saying so if it can't; on GNOME it switches the setting off and on, because the shortcut is a toggle. #3 a failed load of a saved session asks Keep It or Start Fresh; Keep It turns the machine off and the next Start tries again, not a Try Again in place, because a timed-out load may still be running. #4 three missed polls in a row, not one. #5 Start, including `avmctl`, is refused and spoken during a Restore. #6 a device counts as a keyboard by any of its usages, and a held Bluetooth keyboard goes back after two checks find the Mac with no other (helper 0.4.42). #7 a small shell process restores the Caps Lock mapping within a second of AVM dying. #8 the words now say whether the VoiceOver key went in. The offer stays used, deliberately: it's about Setup Assistant, which is over by then, and the spoken line gives the key. #9 one "a machine has the keyboard" check covers macOS guests. #10 `format=raw` on both install-disc drives, which stops QEMU following a backing file.

**Verified:** Debug build, 174 unit tests (1 skipped). Live on the final code: Debian screen reader setup, control socket, save and resume, send file; Windows screen reader setup, save and resume, control socket, send file, restore undo. An independent read of the diff found six problems: four corrected, #8's offer left as above, and one left open (a time-out after Apply stopped the reader doesn't restart it; GuestWatch covers it where it can). The Caps Lock watch's shell loop was tested with a stand-in for `hidutil`.
**Not run live:** Apply starting a stopped reader again (the jobs prove the setup swap; none confirms a reader was running to stop), the Keep It question (test jobs take the old path), an `avmctl` request over 15 seconds, a Bluetooth give-back, Force Quit restoring Caps Lock, the macOS guest paths, Sparkle's hold, a Start refused during Restore, and the imported-ISO case.

**Checked by hand:** findings marked ✓ were re-read against the code by the author of this report after the reviewers. "Inferred" means the AVM side is traced and the outcome depends on platform behaviour that was not run.

**Verdict on the 0.4.41 fixes:** most hold up. One made things worse: the 15-second limit on control socket lines breaks `avmctl` for slow requests (#1). Three are incomplete: Apply still stops the screen reader first (#2), Sparkle's hold misses macOS guests (#9), and the earlier hint file can say "Saved" falsely after a crash (#14).

**Reviewers found clean:** memory handling in `usbstream.c`; XPC argument checks; the release gates (commit, notarization, stapling, update key, build number); QMP reply matching and the bounded write; archive path and symlink handling; quoting of machine and user names into answer files; Windows Apps helper 9's request handling; the keyboard lock's teardown and escape key; password handling in logs.

## Fix first

1. ✓ **`avmctl` reports failure for any request that takes over 15 seconds, and it is a 0.4.41 regression.** `AVM/ControlServer.swift:125-133`, client at `:419`. `readLine` is shared. The client's first read blocks until the reply starts; if that is past the deadline, one byte is kept, the loop ends, the JSON fails and the tool prints "AVM didn't answer." The save or send succeeded, and a script that retries acts on a machine already saved. The live control socket job only sends short requests. Fix: apply the limit on the server side only.
2. ✓ **Apply Screen Reader Setup stops the reader first and promises a restart nothing performs.** `AVM/ScreenReaderSetup.swift:180, 213, 221`, `AVM/GuestWatch.swift:187, 200`. A bad zip leaves the guest with no reader, though the settings are safe. On success AVM says it "is starting" the reader, but only GuestWatch can, about 30 seconds later, and not if that setting is off or for Orca outside GNOME. The user hears silence after being told speech is coming. Fix: validate first, stop just before the swap, and have Apply start the reader and confirm it, on success and on failure.
3. ✓ **Any failed load of a saved session deletes it without asking.** `VM/VMManager.swift:4972-5002`. A slow external drive past the job limit, a QMP timeout, or a QEMU update that changes device state (inferred) all reset the guest and delete the session. This is the loss fixed for macOS guests in the last audit. Fix: stop before `system_reset`, keep the snapshot, offer Try Again or Start Fresh.
4. ✓ **One slow status poll fails a whole guest job while it keeps running.** `VM/VMManager.swift:5209`. A single 10-second "no answer" throws out of the loop, whatever the job's limit. Apply can say it failed while the guest finishes the swap. This may be the unexplained Windows failure in the last audit, though that can't be proven. Fix: keep polling to the deadline and give up only after several failures in a row.
5. ✓ **Start isn't refused while a Restore is running.** `VM/VMManager.swift:1317`, `views/SettingsView.swift:1161`; `RestorePoints.restoring` is read only by Quit. A Dock launch of a Windows app or `avmctl start` can start QEMU and swtpm between the rollback and the TPM swap. Windows may then ask for its BitLocker key, or Restore fails on the lock. The dashboard's own Start was not traced. Fix: refuse at the top of `startVM`, by machine id.
6. ✓ **The "Mac keeps one keyboard" rule has two holes for Bluetooth.** `AVMUSBHelper/BluetoothHold.swift:467-488, 116-121`. It tests only the primary usage, and a Mantis Q40's is on the braille page (the file's own comment), so a braille display that is the Mac's only keyboard passes. It also runs once: unplug the USB keyboard after the Bluetooth one goes to Windows and the Mac has none, with no 6-second giveback like `KeyboardHold.checkWhileHeld`. Fix: test all usage pairs, and add a two-strike check to the 3-second watch.
7. **Force Quit while in a machine leaves Caps Lock as F19 for the whole Mac.** `input/CapsLockRemapper.swift:181-290, 315`. The last audit made Force Quit the way out of a hang, but restore runs only at unlock, normal quit or next launch. If Caps Lock is the VoiceOver key, VoiceOver commands die when they are needed most, with no explanation. A crash does the same. Fix: a small watcher process that restores the mapping when AVM dies.
8. ✓ **macOS auto setup says "with VoiceOver on" when it wasn't turned on.** `AVM/MacAutoSetup.swift:328-341, 138`, `AVM/MacGuest.swift:496-499`. A missing Command key still returns `.done`, and the key press itself is `try?`. The user is told speech is on in a silent guest, and the VoiceOver offer is then marked used. Fix: report whether the key went through, choose the words from that, and keep the offer.
9. ✓ **The hold on Sparkle's window ignores macOS guests.** `app/AVMUpdater.swift:180, 220`, also `:472`. Only `FocusLockManager.isLocked` is tested, and macOS guests use `keyboardInGuest`. Keys meant for the guest can go to the update window, with Install focused (Sparkle's focus behaviour inferred). Fix: one "a machine has the keyboard" check, and post the unlock notice from `setKeyboard(inGuest: false)`.
10. ✓ **An imported package's install ISO is opened with no format set, so a crafted one can read Mac files.** `VM/VMManager.swift:2738, 2757`, `AVM/MachineArchive.swift:390-405`. Only the disks are vetted for backing files. An `install-avm.iso` that is really a qcow2 backed by a Mac file would be opened with AVM's rights (QEMU's probing inferred). It needs someone to send a crafted package. Fix: `format=raw` on both lines, and leave the ISO out of imports.

## Medium-low

11. **Quit Now during a saved-state load loses the session and gives a false reason.** `app/AVMApp.swift:1443-1456`, `VM/VMManager.swift:4413-4424, 4928`. Quit ends with the empty marker still there, because the catch that removes it never runs (AppKit timing inferred). Next Start says it couldn't be carried on and deletes it. A restore point's note stays set aside. Fix: undo the marker and note in `terminateForQuit` when a load is under way.
12. ✓ **The Permissions window can open over a machine that has the keyboard.** `AVM/Permissions.swift:227-231`. No check of either keyboard mode, 3 seconds or more after launch, so with Start When AVM Opens typed keys go to that window. The escape chord still works, so it's not a trap. Fix: the wait-until-on-the-Mac pattern from `ReleaseNotes`.
13. ✓ **"AVM's USB helper restarted" can be untrue.** `AVMUSBHelper/main.swift:684-705`, `AVM/USBHelperClient.swift:552-561`. Both refusals send the same empty reply as success, and with a stuck stream the old process lives 3.5 seconds, past the client's 2-second wait, and answers. An attach in that window is lost. Fix: a real result, a per-process id the client requires to change, and an exiting flag that refuses attach.
14. ✓ **A crash during Save leaves a false "Saved".** `VM/VMManager.swift:4864`, `AVM/QEMUSavedState.swift:153`. The hint now comes before the snapshot and is also what the list reads. Start then boots fresh and says nothing. Fix: a separate pre-snapshot note, and speak when a hint has no snapshot.
15. ✓ **Send File reads the Mac file on the main actor.** `VM/VMManager.swift:5373, 2049`. An iCloud file not yet downloaded or a stalled volume stops menus, Force Stop and speech for as long as it takes (blocking inferred). Fix: read each chunk off the main actor.
16. **A good cached screen reader is ignored when the feed answers but the download fails.** `AVM/ScreenReaderInstallers.swift:198, 203, 251`. Windows then installs with Narrator only. Copies cached before 0.4.41 have no record and are skipped offline. Fix: fall back after the download loop; accept an unrecorded copy that hashes to the pinned value.
17. ✓ **Command-Shift-V can't stop typing once the clipboard is empty.** `app/AVMApp.swift:515-519`. AVM promised that key would stop it, but the empty-clipboard check comes first and typing goes on. Fix: check `isTypingText` first.
18. **AVM's own keys are lost silently with no input channel.** `views/VMView.swift:825-828`, `:1656-1659`. Read Screen and Speak Status do nothing during a restart, though the Tour says they work then. A stale held key can fire on the next entry. Fix: run the deferred command regardless, and clear it when the lock ends.
19. ✓ **One failed console query ends a Bluetooth braille display's session with a false reason.** `AVMUSBHelper/BluetoothHold.swift:118-120, 557-561`, `KeyboardHold.swift:492-495`. A nil answer counts as "you left the Mac's screen", and the USB watch was deliberately written the other way. How often nil occurs is inferred. Fix: treat nil as no change.

## Lower

20. **A half-made second drive is marked done.** `AVM/DiskWatch.swift:169`, `AVM/MachineDrives.swift:233`. Once initialized the disk isn't RAW, so the retry answers "already" with no volume made.
21. **The automatic Apply on a new machine gets one try.** `AVM/GuestWatch.swift:181-183`. The flag is cleared before Apply runs; #4 makes a false failure plausible.
22. ✓ **The profile path is built from the account name.** `AVM/ScreenReaderSetup.swift:60, 179`. For a renamed account or a `name.PC` folder, Apply writes to a new folder and reports success. Fix: read `Win32_UserProfile.LocalPath`.
23. **The Linux ISO download has no free-space check.** `views/LinuxISODownload.swift:222-253`. A read error in `verify` (`:345, 369`) also reads as a bad checksum and deletes the file.
24. **Any other partial download stalls the Windows ISO watcher.** `VM/WindowsISODownloader.swift:203-223`.
25. **Packages carry Mac-specific settings.** `AVM/MachineArchive.swift:168-197, 464-508`. Sound device names go out; a backup schedule and similar settings come in.
26. **Save and Quit's device messages can be wrong.** `VM/VMManager.swift:4819`, `app/AVMApp.swift:1364, 1404`.
27. **Force Stop doesn't track a restore point being made at Start.** `VM/VMManager.swift:1522-1525, 1847`. Corrects itself at the next Start.
28. **A failed helper version check isn't retried that run.** `AVM/USBHelperClient.swift:495-502, 517-518`. AVM can run on an old helper after an update.
29. **A device set aside as stuck is never reported.** `AVMUSBHelper/main.swift:423-433, 553-556`. AVM keeps saying it's attached.
30. **A keyboard hold landing after the 30-second limit can stay seized.** `AVM/USBHelperClient.swift:857-865, 898`. Partly inferred.
31. ✓ **Opening a Windows app from the Dock during shutdown gets no answer.** `AVM/WindowsApps.swift:747`.

**Hardening, not defects:** `Tools/promote-release.sh:19-31` lacks publish-release's check for uncommitted `appcast.xml` edits. The Tour's Next and Back controls change or disable under the VoiceOver cursor at the ends (`AVM/Tour.swift:111, 115`, inferred, needs a VoiceOver test).

**Not read closely:** `Resources/autounattend.xml`, distro setup scripts beyond account quoting, `AVM/AccessibilityAudit.swift`, every line of `views/SettingsView.swift` and `views/SetupView.swift`, `SaveResumeTestJob`.
