# AVM code audit, November 9, 2026 (fourth)

Read-only audit of `next` at `0311bcf`, the published 0.4.42 (62). Five independent reviewers: the 0.4.42 changes themselves (`git diff v0.4.41..HEAD`); the machine lifecycle core (all of `VMManager.swift`, sessions, saved state, restore points, backups, quit); every trust boundary (root helper, control socket, guest to host, host-to-guest scripts, secrets, updates and downloads); install pipelines and guest integration; and what the user touches and hears, with input capture. Nothing was built, run or changed.

**Status: the eleven "Fix first" shipped in 0.4.43 (2026-11-10); #12 to #31 fixed on `next`, uncommitted, the same day; #32 left unverified.** No High findings. 32 findings: 11 "Fix first", 11 Medium-low, 10 Lower.

**How the eleven were fixed** (each site carries a dated comment naming its number):

1. `AVMPasteboard.isPrivate` (concealed or transient marks) gates every path that offers the Mac's clipboard to a SPICE guest, and a guest's clear no longer erases a private copy; `MacClipboard` uses the same test. 2. New QEMU patch `qemu-10.0.12-utm+no-host-loopback.patch` turns on libslirp's `disable_host_loopback`; QEMU rebuilt by hand, the old library kept as `libqemu-aarch64-softmmu.before-loopback.dylib`, the patch checked against a fresh source and recorded with `--mark-built`. 3. `FocusLockManager` records the machine it locked for (`lock(machine:)`, `holdsKeyboard(for:)`); ending, entering, a window becoming key, the screen going away, the Status column and Speak Status go by it; a row's device button no longer renames the keyboard's machine, and the name follows the current machine again at unlock. 4. Only Start Fresh discards; any other answer keeps the saved session. 5. `lostfs` added to `DiskWatch.answer`, with a test of every word. 6. The disk watch checks QEMU's status every ten seconds, the rest each minute as before; the dead RESUME line from 0.4.42 removed (events are still not read). 7. Setup reports JAWS only when `jfw.exe` is in a version folder. 8. The serial port is a `-chardev file` with `append=on`, emptied at each start; `DiskWatch.trimSerialLog` cuts it to its last 4 MB past 32 MB; Report a Problem reads its last 8 MB. 9. `prepareNVRAM` sets aside a store that isn't exactly 64 MiB as `nvram-wrong-size.fd` (one kept, never exported, removed by Reinstall), writes the plain store atomically and checks it, and stops the start with a spoken reason when it can't. 10. Save and Apply stop at a link anywhere on the way to NVDA's folder; the copy skips links (`/XJ`); the setup is unpacked in `C:\ProgramData\AVM`, given the user's rights there, and moved in whole with `Directory.Move`; old copies go with `rmdir /s`. A swap in the instant between check and move remains possible in a guest with other accounts. 11. After a failed download, the newest verified copy in the cache is installed, and the version is said.

**Independent review of the fixes:** a read-only reviewer passed eight and found holes in three, all corrected. #3: Speak Status and the Status column still named the current machine; the menu kept the locked machine's name after unlock and acted on another; `lock()` now takes the entering machine. #10: an `icacls /reset /t` after the move could be pointed through a link swapped in (the rights are now given before the move, inside AVM's folder, and the exit code is checked). #9: set-aside stores piled up and travelled in exports. It also noted a guest's clipboard clear erasing a private Mac copy (fixed). Left: #7's second half (checking the process list before "talking"); QMP events other than the io-error pause (a guest panic) are still unseen; the trim runs on the main actor (a 4 MB read and write at most every ten seconds, only for a guest flooding its port).

## Fix first

1. ✓ **Passwords copied on the Mac are offered to Windows and Linux guests.** `views/VMView.swift:994-1035` (`macPasteboardMayHaveChanged`, `canReadItem`, `data(for:)`). The macOS-guest path drops copies marked `org.nspasteboard.ConcealedType` or `TransientType` (`AVM/MacClipboard.swift:98-108`); the SPICE path doesn't. A password copied from Passwords or 1Password goes to every running SPICE guest at the next entry, where any clipboard reader, or Windows' synced Clipboard History, gets it. Fix: apply `MacClipboard.privateTypes` in all four SPICE methods.
2. ✓ **Every guest can reach the Mac's loopback-only services, including other machines' "This Mac only" Remote Desktop.** `AVM/GuestWatchLogic.swift:421` (`user,id=net0`), `AVM/RemoteDesktopAddress.swift:47`. QEMU user networking maps 10.0.2.2 to the Mac's 127.0.0.1 by default. A hostile guest reaches machine B's Remote Desktop forward (needing only its password) and any local dev server, model server or Docker TCP socket. "Reachable from: This Mac only" is untrue. Fix: set libslirp's `disable_host_loopback` in the bundled QEMU (`-netdev user` doesn't expose it, so a patch); at least correct the wording.
3. ✓ **The keyboard lock belongs to "the current machine", not the one that has the keyboard.** `AVM/MachineSessions.swift:251`, `views/VMView.swift:603`, `views/ContentView.swift:1081-1138`. With the keyboard in A, VoiceOver on the dashboard, the user presses B's Attach USB Device or Return Devices: B becomes current. A then shuts down; neither `end` nor `onDisappear` unlocks. Menu bar and Dock stay hidden, Caps Lock stays F19 (VoiceOver's Caps Lock commands dead), Speak Status says the keyboard is in B, and when B's window becomes key the keys go into B with no "Entering B". Control-Command-Escape still gets out. VoiceOver steps inferred. Fix: FocusLockManager records the machine it locked for; unlock when that machine ends; row buttons don't change current while another machine holds the lock.
4. ✓ **The Keep It question treats every answer but Keep It as Start Fresh.** `VM/VMManager.swift:5068`, `AVM/USBPlugPrompt.swift:232, 280`. The Keep It alert can open over a USB-plug question (it runs from the run loop in common modes). An unplug or another machine stopping makes `USBPlugPrompt` call `NSApp.abortModal()`, which ends the innermost modal: Keep It's. The answer is `.abort`, the machine is still starting, and AVM resets it and discards the saved session nobody chose to discard. AppKit behaviour inferred. Fix: Start Fresh only on `.alertSecondButtonReturn`; anything else keeps it.
5. ✓ **0.4.42's `lostfs` answer is never recognised.** `AVM/DiskWatch.swift:205`. `answer()`'s word list lacks `lostfs`, so it returns nil and every Start still says "couldn't be made ready. AVM tries again at its next Start", the promise the seventh audit's #22 removed. Fix: add the word; add a unit test.
6. ✓ **0.4.42's "RESUME event" fix, and all QMP event handling, is dead code.** `VM/VMManager.swift:3943-3983`. `handleQMPLine` has no callers (its own comment says so); `sendQMPCommand` skips event lines. STOP, SUSPEND, GUEST_PANICKED and RESUME never reach `state`. A pause QEMU makes itself (a disk error with werror=stop) is seen only by DiskWatch's `query-status` poll, once a minute: up to 60 seconds of "Running" over a frozen guest, keys typed into nothing. The `resumeVM` half of #23 works. Fix: act on event lines in the skip loop of the single reader, or poll `query-status` more often while running; correct the seventh audit's report.
7. ✓ **"JAWS is talking in it" is said because a folder exists.** `Resources/autounattend.xml:237`, `VM/VMManager.swift:930-933`. `jaws-installed` is written if `Freedom Scientific\JAWS` exists; a JAWS install killed at 30 minutes, or one failing after making the folder, leaves it without `jfw.exe`. First logon starts nothing, but the user hears that JAWS is talking and no Narrator advice. Fix: test for `jfw.exe` with the same `for /d` as first logon; before saying "talking", confirm the reader in the process list GuestWatch already gathers.
8. ✓ **`firmware-serial.log` grows without limit, and Report a Problem reads it whole.** `VM/VMManager.swift:3028-3029`, `DiagnosticLogExporter.swift:240-262, 315`. Linux guests log to `ttyAMA0`. A looping guest, or root writing to the port, fills the Mac's disk; the exporter then loads and regex-scans gigabytes on export. Fix: cap the file (QEMU's `-chardev file` has no cap, so a pipe AVM drains into a ring, or truncate at Start and on a size watch), and have the exporter read the tail.
9. ✓ **A short write of `nvram.fd` stops every later Start.** `VM/VMManager.swift:2663-2682`. The plain firmware file is written with a plain `Data.write`, unchecked, and a failure is only logged. With the disk nearly full a truncated file can stay; every later Start keeps it and QEMU refuses a pflash that isn't 64 MiB, heard as "stopped unexpectedly", even after space is freed, and restore points copy it. The Secure Boot path checks the size. Partial file on ENOSPC inferred. Fix: write `.atomic`, recreate anything not exactly 64 MiB on reuse, stop the start with a spoken error if the write fails.
10. **Screen reader Save and Apply run as SYSTEM in a folder the signed-in user owns.** `AVM/ScreenReaderSetup.swift:95-110, 180-211`. Save's `robocopy /E` follows junctions (no `/XJ`); Apply's `Remove-Item -Recurse -Force`, `ExtractToFile` and `Move-Item` work on `nvda-avm-new` and `nvda-before-avm*` in the user's `AppData`. A standard user in a multi-account guest who plants a junction gets SYSTEM to copy, delete or write elsewhere. Inside the guest only; PowerShell 5.1's delete through a link inferred. Fix: do the copy, unpack and move as the user (a one-off scheduled task), or `/XJ` and refuse any reparse point on every path.
11. **A verified cached screen reader installer is ignored when a newer one fails to download.** `AVM/ScreenReaderInstallers.swift:197-253`. `newestGoodCopy` is used only when the lookup fails. NV Access or winget list a new release, three tries fail (a CDN hiccup, or JAWS's 1.5 GB hitting the hour limit), and Windows installs with Narrator only though the previous verified installer is in the cache. Fix: fall back to `newestGoodCopy` after the last failed try and say which version.

## Medium-low

12. **The dashboard still reads stopped machines' folders on the main thread.** `views/ContentView.swift:611, 690, 702` (`QEMUSavedState.looksSaved`), through `VMConfiguration.resolvedStoragePath`. A machine on a sleeping or gone drive stalls every redraw, and a missing folder lists `/Volumes` and reads each UUID. The fifth audit's #17 moved only the macOS row to `StorageWatch`. Fix: publish a QEMU saved hint from `StorageWatch`.
13. **Force Stop during a Save can throw away a finished save silently.** `VM/VMManager.swift:4925-4934`. If the snapshot landed before AVM's poll saw the job end, the catch writes the "carried on" marker and drops the hint; the next Start deletes the session quietly. `createRunningRestorePoint` checks this case. Fix: check `snapshotTags` in the catch; keep and say "saved" if it landed, otherwise say the save was abandoned.
14. **A leftover `saved-state` snapshot makes the next Save fail, and Save and Quit then refuses to quit.** `VM/VMManager.swift:5101-5109, 4923`, `AVM/QEMUSavedState.swift:138-146`. Deletes after a resume and at Start can fail with only a log; `snapshot-save` doesn't overwrite (inferred from QEMU). The second try works. Fix: delete the tag on every device before `snapshot-save`.
15. **A Bluetooth device waiting for the Mac to have a keyboard is re-sent and refused at every Bluetooth arrival.** `AVM/BluetoothDevices.swift:463-476`. Each try hot-plugs a bridge into the guest, removes it, and speaks "stayed on the Mac", three or more times per arrival; a USB keyboard coming back for the Mac triggers nothing. Fix: retry quietly or ask the helper before adding the bridge; watch any keyboard arrival.
16. **GuestWatch now restarts Orca a user turned off.** `AVM/GuestWatch.swift:213-215, 274-279`. Before 0.4.42 the "no reader a minute after sign-in" path only advised; now it sets `screen-reader-enabled` off and on at every boot, rewriting the setting for later logins too. Fix: start Orca there only if the setting is already on, or keep that path advisory.
17. ✓ **Cinnamon is never matched, so Orca can start with no display.** `AVM/GuestWatch.swift:277`. `cinnamon-session` is 16 characters; Linux cuts process names to 15, and `pgrep -x` never matches. The fallback is the user's newest process, which may have no `DISPLAY`. Fix: match `cinnamon-sessio`, or read the session's environment from `loginctl`.
18. **Renaming a running machine leaves the old name in what AVM says.** `AVM/MachineSessions.swift:128`, `VM/VMManager.swift:3665, 3699`, `AVM/USBPlugPrompt.swift:414`, `views/ContentView.swift:1607`. Speak Status says "Work PC is running… The keyboard is in Win11"; Entering, the menus, USB questions and Read Screen keep the old name. Fix: refresh the session's and manager's name when the store saves a running machine.
19. **A start's middle steps carry on after Force Stop and can overlap the next Start.** `VM/VMManager.swift:1471-1538`. No `ensureStillStarting()` from `plan()` until 1562; the old start's media removal, `mren` on the answer image and restore-point snapshot can run beside the new start's. Short window. Fix: `ensureStillStarting()` after every await there.
20. **A saved NVDA setup carries add-ons into every other machine.** `AVM/ScreenReaderSetup.swift:100-103`. Only logs and `updates` are excluded; with the setting that applies the setup to new installs, an add-on from a compromised machine runs in all of them. Fix: exclude `addons` and `scratchpad`, or name them and ask.
21. **Guest-controlled text is spoken in AVM's voice without a limit.** `AVM/WindowsApps.swift:787-791`, `AVM/Windows3D.swift:76-89`, `VM/VMManager.swift:5386-5392`. A hostile guest can make AVM say, after "Reason:", what sounds like a Mac password prompt. Fix: speak a fixed sentence; log a bounded first line.
22. **"Add a second drive" is dropped silently for a machine that started while Settings was open.** `views/SettingsView.swift:1748, 1774, 2001-2020`. The message says changes take effect at the next start; the drive never comes. Fix: say it wasn't added and to shut down first.

## Lower

23. **Any machine's SPICE agent releases the devices held for the watched machine.** `views/VMView.swift:2361-2374`, `AVM/USBPlugPrompt.swift:93, 193-202`. Two machines starting together: B's agent releases A's held braille display while A's firmware still resets USB.
24. **The wizard's "Stop the download?" is untrue for the browser download.** `views/SetupView.swift:201-205`. The browser keeps downloading; AVM only stops watching.
25. **The keyboard offer can come up unheard, and Return declines it for good.** `AVM/KeyboardOffer.swift:45-73`. With VoiceOver off it isn't spoken; Not Now is added to the declined list silently.
26. **A load that finishes during the new two-minute wait is still treated as failed.** `VM/VMManager.swift:5036`. Fix: return the job's status and `cont` on success.
27. **A repartitioned Linux second drive can leave `UUID=` in fstab.** `AVM/DiskWatch.swift:189-196`. The failure is spoken at every Start.
28. **Drive C's `same` also covers a partition after C.** `AVM/DiskWatch.swift:148-155`. Since #18 that is silent; the user grew the disk and C never got it. Inferred.
29. **NVDA's winget fallback asks for x86.** `AVM/ScreenReaderInstallers.swift:114`. NVDA 2026 is 64-bit; the fallback falls to the pinned 2026.2 every time. Inferred.
30. **An `install.esd` ISO is called "not a Windows 11 installer".** `VM/WindowsInstallPipeline.swift:914-918, 1034`.
31. **Debian testing and alpha discs are refused as older than 12.** `VM/UbuntuInstallPipeline.swift:640, 673`. The first number in `/.disk/info` is the alpha's.
32. **Unverified: macOS automatic setup under a non-US keyboard layout.** `AVM/MacAutoSetup.swift:371-388`. If the VNC server maps keysyms to US key positions, an AZERTY or QWERTZ region types a different password. One run in a German or French region would settle it.
